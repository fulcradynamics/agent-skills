# fulcra-get-started

The first thing to read if you have just arrived and none of this means anything yet.

Fulcra gives you one place to keep your real-world data — and, crucially, one place your agents can reach it. The data belongs to you rather than to whichever assistant happens to be holding it, which is what lets you hand the same context to a new agent tomorrow instead of starting over.

This skill is not a tour of the environment. It gets you connected, then works with you to pick a real problem worth solving — something new you want to make, something specific that is broken, or something you already have that could be better — and pushes that far enough to be real. By the end you should have a view of your own data, a workspace where the work continues, and a way to see what has been done and what comes next.

Then it hands you off, which is the point. Getting started is deliberately the shallow end; the depth is in the skills it breaks you out into on the way — `fulcra-ingest` for pulling in data from services you already use, `fulcra-workspaces` for the place the work lives, `fulcra-tracking` for recording what matters as you go, and `fulcra-rapid-prototype` (in fulcradynamics/community-skills) when the direction you picked wants building rather than describing.

Start here, and expect to leave quickly.
